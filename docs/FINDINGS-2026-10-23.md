# 根因分析 · 2026-10-23 · 关掉插件后模型选择器消失

## 用户报告

> 该插件的显示bug还是没有修好，现在一旦关掉该插件，就会导致模型选择器从消息栏直接消失

「关掉该插件」→ 消息栏（composer bar）里的模型选择器**整个消失**，官方那颗也不回来。

## 已验证的事实（全部来自随包发布的官方源码，非猜测）

### 1. 座位槽由 composer 声明

`@deepseek-ai/dsh-client-ui-conversation/lib/client.js:19908`

```js
"conversation.input.model": { kind: "single", scope: "session" }
```

`single` 槽，同优先级只能有一条注册；**最低优先级的那条渲染**（shadowing）。

### 2. 官方 selector 的注册形状

`@deepseek-ai/dsh-client-ui-model-selection/lib/client.js:1903`

```js
scope.slots.inject("conversation.input.model", () => scope.slots.register({
  name: "conversation.input.model",
  locale: NS,
  children: { "conversation.input.model.label": {
    kind: "single", scope: "session", inline: true
  } },
  inject: (sessionId) => { … }
}, ModelSelect));
```

**它同时注册座位槽、并声明子槽 `conversation.input.model.label`。**

### 3. 注册表：子槽声明是**独占**的

真实 `SlotCore`（从 `dsh-web-frontend/dist/assets/index-CN7NIWNw.js` 里原样抽出的
`SlotCore.register`）：

```js
if (e.children) for (const h of Object.keys(e.children)) {
  const m = this.records.get(h);
  if (m?.spec) throw new Error(`slot "${h}" is already declared (by ${m.declaredBy})`)
}
```

**同一个子槽只能被「一个」条目声明一次。** 谁后注册，谁抛。

### 4. 释放：子槽的声明归**最后声明它的那个条目**

```js
releaseEntry(e) { … this.releaseChildren(e.children) }
releaseChildren(e) {
  for (const t of Object.keys(e)) {
    const r = this.records.get(t);
    r.spec = void 0;            // ← 声明被清空
    r.declaredBy = void 0;
    r.parent = void 0;
    r.declarationEpoch += 1;
    r.entries = i1;
    this.notifyDeclaration(r);
    for (const n of i) this.releaseEntry(n);
  }
}
```

条目被 dispose 时，它**声明过的**子槽会**无条件塌陷**（spec 清空）。

### 5. 渲染器：子槽授权按**条目**算，不是按槽算

`@deepseek-ai/dsh-client-ui-renderer/lib/client.js`

```js
binding = (key, owner, opts) => {
  if (!host.isLive(entry)) throw new StaleAuthorizationError(…)
  const declared = entry.children?.[key];
  if (declared === void 0) throw new SlotOwnershipError(…)
  …
}
```

`renderSlot` 只允许调用**自己那条 entry 声明过的**子键；`renderSlot` 这个 prop 也**只有在
entry 声明了 children 时**才会被装配进 kit：

```js
if (entry.children !== void 0) {           // ← 大意
  kit["renderSlot"] = boundRenderSlot(host, entry);
  …
}
```

## 复现（用真实随包发布的 SlotCore 跑）

`_tools/seat_lifecycle.mjs`，两段：

**场景 A —— 官方先注册、我们后注册：**

```
after shipped registers:  winners 1 -> shipped ModelSelect
ours registers            -> THREW: slot "conversation.input.model.label" is already declared
after our plugin disabled: winners 1 -> shipped ModelSelect      ← 正常
```

**场景 B —— 我们先注册（priority -1）、官方后注册（真实顺序）：**

```
after ours registers first:  winners 1 -> our Selector
shipped tries to register   -> THREW: slot "conversation.input.model.label" is already declared
>>> disable our plugin <<<
after our plugin is disabled: winners 0   <-- NOTHING RENDERS
                             child spec  UNDEFINED (collapsed)
```

**场景 B 就是用户报告的现象**：官方那条**从未进入 ledger**（注册时抛错），
所以关掉我们的插件之后，座位上**一条注册都没有** → 模型选择器从消息栏彻底消失。

## 根因（一句话）

我们和官方**都**声明了同一个子槽 `conversation.input.model.label`。
子槽声明是独占的：**谁后注册谁抛错**。我们抢在前面（`immediately: true` 的动态包先注册），
于是**官方的注册被静默地打掉**；等我们被关掉时，座位上什么都不剩 ——
官方那颗从来没有上过 ledger。

第 16 条（"必须声明同样的子槽，否则徽标消失"）和第 19 条（"必须补 `remote.session`"）
都是**真问题**，但两者合起来把插件推进了一个**死结**：

- 不声明子槽 → 官方那条能注册，但它声明的子槽和我们的 `renderSlot` 授权对不上
  → 徽标（1017）看不见；
- 声明子槽 → 官方那条注册时抛错 → 我们一关，座位空了 → **模型选择器消失**。

## 修法（选定）

**我们不再声明这个子槽，也不再调用 `renderSlot` 去渲染它。**

理由：子槽 `conversation.input.model.label` 的**所有者**是官方那条 entry
（它声明的，它 render 的）。我们要做的是**替换座位上的那颗按钮**，
而不是**接管这个子槽的声明**。

代价：1017 徽标（模型名后面的「1017」）在我们接管座位期间**不再显示**。
这是可接受的取舍 —— 徽标是装饰，模型选择器消失是**功能性损坏**。
而且徽标只在**官方那颗**渲染时才画得出来（子槽由官方 entry 声明、
由官方 entry 的 `renderSlot` 调用触发）；我们要显示它，就得抢声明，
而抢声明就等于把官方那条打死。这不是可以两头都要的局面。

**具体改动：**

1. `client.js` 的注册**去掉 `children` 字段** → 官方那条能正常注册，
   座位 ledger 上永远有两条（我们 -1、官方 0），关掉我们官方那条立刻接管。
2. 组件里**去掉 `renderSlot('conversation.input.model.label', …)` 调用**，
   直接渲染目录里的模型名（就是现在的 `fallback` 分支）。
3. 顺带修掉一个隐患：`model && renderSlot` 这个守卫要换成「没有 `renderSlot`
   就用模型名」—— 没有 `children` 就没有 `renderSlot` prop，
   `renderSlot` 会是 `undefined`。

## 断言

用**真实随包发布的 SlotCore**（从 asar 里的 web-frontend bundle 抽出来）复跑
上面两段生命周期：

- 场景 B：官方那条**必须**成功注册（不抛错），座位 winners 必须是 1；
- 关掉我们之后，座位 winners 必须是 1，且渲染的是**官方**那颗。
